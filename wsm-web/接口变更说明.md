# 接口变更说明

## 概述

前端简化了仓库结构，从原来的四级（仓库→库区→货架→库位）改为三级（仓库→货架→商品）。

## 需要后端改动的接口

### 1. 货架接口变更

**原接口**：`GET /warehouse-shelves/area/{areaId}`
**新接口**：`GET /warehouse-shelves/warehouse/{warehouseId}`

说明：货架从关联库区改为直接关联仓库。

**货架表结构变更**：
```sql
-- 原字段
area_id  -- 库区ID

-- 新字段
warehouse_id   -- 仓库ID
category_name  -- 商品分类名称（如：男拖、女拖、童拖）
```

### 2. SKU 接口变更

**新增接口**：`GET /skus`（获取所有SKU列表，支持分页）

说明：原接口 `GET /skus/product/{productId}` 只能按商品查询，新增一个支持分页查询所有SKU的接口。

**请求参数**：
```
GET /skus?page=1&size=10&keyword=xxx&status=1
```

| 参数 | 类型 | 说明 |
|------|------|------|
| page | int | 页码，默认1 |
| size | int | 每页数量，默认10 |
| keyword | string | 搜索关键词（SKU编码/名称） |
| status | int | 状态筛选（1启用/0禁用） |

**响应格式**：
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "total": 100,
    "list": [
      {
        "id": 1,
        "productId": 1,
        "shelfId": 1,
        "shelfCode": "A01",
        "skuCode": "SKU001-42",
        "name": "拖鞋-黑色-42码",
        "spec": "黑色/42码",
        "quantity": 100,
        "costPrice": 10.00,
        "salePrice": 29.90,
        "weight": 0.3,
        "status": 1,
        "productName": "男士拖鞋",
        "categoryName": "男拖"
      }
    ],
    "pageNum": 1,
    "pageSize": 10
  }
}
```

**注意**：响应中需要包含 `productName`、`shelfCode` 和 `categoryName` 字段。

**SKU表结构变更**：
```sql
-- 新增字段
shelf_id  -- 货架ID（SKU独立关联货架）
```

### 3. 商品接口变更

**字段变更**：商品表中的 `brand`（品牌）和 `category_id`（分类）字段改为 `shelf_id`（货架ID）

**商品表结构变更**：
```sql
-- 原字段
brand        -- 品牌
category_id  -- 分类ID

-- 新字段
shelf_id  -- 货架ID（关联货架表，分类从货架获取）
```

**商品请求/响应格式**：
```json
POST /products
{
  "spuCode": "SPU001",
  "name": "男士拖鞋",
  "shelfId": 1,
  "price": 29.90,
  "description": "舒适透气",
  "status": 1
}
```

**响应中需要包含**：
- `shelfCode`：货架编码（从货架表关联获取）
- `shelfName`：货架名称（从货架表关联获取）
- `categoryName`：分类名称（从货架表关联获取）
```

### 4. 可以删除的接口

以下接口不再需要：

- 库区相关：`/warehouse-areas/*`
- 库位相关：`/warehouse-locations/*`
- 分类相关：`/product-categories/*`（如果有的话）

### 3. 货架请求/响应格式

**创建/更新货架**：
```json
POST /warehouse-shelves
{
  "warehouseId": 1,
  "code": "A01",
  "name": "男拖区",
  "categoryName": "男拖",
  "status": 1
}
```

**获取货架列表**：
```json
GET /warehouse-shelves/warehouse/1

响应：
{
  "code": 200,
  "message": "success",
  "data": [
    {
      "id": 1,
      "warehouseId": 1,
      "code": "A01",
      "name": "男拖区",
      "categoryName": "男拖",
      "status": 1,
      "createdAt": "2024-01-01 00:00:00"
    }
  ]
}
```

## 前端已完成的改动

1. ✅ 删除页面：库区管理、库位管理、分类管理
2. ✅ 简化货架管理：去掉库区选择，直接选仓库
3. ✅ 更新路由配置
4. ✅ 更新菜单配置
5. ✅ 更新货架类型定义（areaId → warehouseId + categoryName）
6. ✅ SKU页面改为直接显示所有SKU列表（分页+搜索）
7. ✅ SKU表格显示所属商品和商品分类
8. ✅ 新增SKU选择商品时显示分类
9. ✅ 商品管理：品牌字段改为货架号
10. ✅ 商品管理：货架号改为下拉选择（从货架管理获取）
11. ✅ 商品管理：选择货架后自动填充分类
12. ✅ SKU管理：添加货架选择和显示
13. ✅ 出库管理：添加新增出库单入口

## 简化后的数据结构

```
仓库 (warehouse)
  └── 货架 (shelf) - 每个货架对应一类商品
        └── 商品 (product)
              └── SKU (sku)
```

2. 库存可以直接关联到：货架 + 商品 + SKU
