## 二、快递费用模板

### 2.1 首重续重计费类型

**数据库新增字段**：
```sql
ALTER TABLE express_fee_template 
ADD COLUMN template_type VARCHAR(20) DEFAULT 'LADDER',
ADD COLUMN first_weight DECIMAL(10,2),
ADD COLUMN first_fee DECIMAL(10,2),
ADD COLUMN additional_weight DECIMAL(10,2),
ADD COLUMN additional_fee DECIMAL(10,2);
```

**计费逻辑**：
- 阶梯计费（LADDER）：按重量区间匹配费用
- 首重续重（FIRST_CONTINUE）：首重费用 + 续重费用（向上取整）

**示例**：
- 首重 1kg：8元
- 续重每 1kg：2元
- 重量 3.5kg → 8 + 3×2 = 14元

### 2.2 前端自动计算

- 选择模板时加载详情并缓存
- 输入重量时自动计算费用（不调用API）
- 发货管理和退货管理都支持

## 十八、换货后仪表盘 SKU 销量修复

### 18.1 问题现象

- 换货完成后，仪表盘 SKU 销量、TOP SKU 等图表仍显示换货前的旧商品。
- 换出的新商品虽然已经扣库存，但没有进入仪表盘销量统计。

### 18.2 根因分析

- 仪表盘销量统计基于 `outbound_order_item` 汇总，并且只统计 `outbound_order.status = 'SHIPPED'` 且有发货时间的数据。
- 换货发货时会创建新出库单和新出库明细，但新出库单仍停留在 `WAIT_PICKING`，没有写入 `shipped_at`。
- 原出库单被标记为 `EXCHANGED` 后退出统计，但新换出商品没有及时进入 `SHIPPED` 统计口径，导致仪表盘仍表现为旧商品数据没有变化。

### 18.3 修复内容

- 换货发货时保存新出库单的快递公司、快递单号和快递费。
- 原已发货出库单标记为 `EXCHANGED`，不再参与销量统计。
- 新换出商品对应的出库单立即标记为 `SHIPPED`，并写入 `shipped_at`，确保新 SKU 进入仪表盘销量统计。
- 补充 `ExchangeServiceImplTest` 回归测试，覆盖“原出库单退出统计、新出库单进入已发货统计”的场景。
