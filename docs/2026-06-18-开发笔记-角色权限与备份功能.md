# 2026-06-18 Redis缓存、角色权限与备份功能

## 一、Redis 缓存集成

### 背景

项目之前没有任何缓存，所有请求直接查库。仪表盘接口每次执行 50+ 条 SQL，JWT token 无法撤销，基础数据反复查库。

### 实现内容

#### 1. 基础配置

- 添加 `spring-boot-starter-data-redis` 依赖
- 配置 `RedisConfig.java`：JSON 序列化（Jackson + JavaTimeModule）
- 封装 `CacheService.java`：get/set/delete/hasKey/getOrLoad 工具方法

#### 2. 仪表盘缓存

- `ReportServiceImpl.getDashboard()` 缓存 5 分钟
- 缓存 key：`cache:dashboard`
- 订单/出库/退货/换货状态变更时自动清除缓存

#### 3. JWT 黑名单

- `JwtUtils` 新增 `getTokenRemainingTime()`、`getTokenBlacklistKey()`
- `JwtAuthFilter` 请求时检查 Redis 黑名单
- `UserController` 新增 `POST /api/auth/logout`，登出时写入黑名单
- 缓存 key：`jwt:blacklist:{token_hash}`，TTL = token 剩余有效期

#### 4. 基础数据缓存

| 数据 | 缓存 Key | TTL | 清除时机 |
|------|----------|-----|----------|
| 平台列表 | `cache:platforms:enabled` | 30 分钟 | 平台增删改 |
| 快递公司 | `cache:express:companies` | 30 分钟 | 快递公司增删改 |
| 仓库详情 | `cache:warehouse:{id}` | 30 分钟 | 仓库增删改 |
| 分类树 | `cache:category:tree` | 30 分钟 | 分类增删改 |
| 角色列表 | `cache:roles:all` | 30 分钟 | 角色增删改 |
| 用户信息 | `cache:user:{id}` | 10 分钟 | 用户信息变更 |
| SKU 查询 | `cache:sku:code:{code}` | 10 分钟 | SKU 信息变更 |
| 快递查询 | `cache:express:query:{no}:{carrier}` | 30 分钟 | 自然过期 |

#### 5. 缓存清除时机

- 订单状态变更 → `OrderServiceImpl.updateStatus()`
- 订单导入 → `OrderServiceImpl.importOrder()`
- 出库确认 → `OutboundServiceImpl.confirm()`
- 退货确认 → `ReturnServiceImpl.confirm()`
- 换货发货 → `ExchangeServiceImpl.ship()`

### 环境变量

| 变量 | 默认值 | 说明 |
|------|--------|------|
| `REDIS_HOST` | `localhost` | Redis 地址 |
| `REDIS_PORT` | `6379` | Redis 端口 |
| `REDIS_DB` | `0` | 数据库编号 |
| `REDIS_PASSWORD` | 空 | 密码 |

### 验证方式

```bash
redis-cli
KEYS cache:*          # 查看缓存 key
TTL cache:dashboard   # 查看过期时间
```

## 二、角色权限管理模块

### 背景

之前系统有角色但没有权限控制，所有用户都能访问所有功能。需要实现 RBAC，让管理员可以配置角色能访问哪些模块。

### 实现内容

#### 1. 后端

**新增文件：**
- `SysPermission.java` - 权限实体
- `SysRolePermission.java` - 角色权限关联实体
- `PermissionMapper.java` + `PermissionMapper.xml` - 权限 Mapper
- `RolePermissionMapper.java` + `RolePermissionMapper.xml` - 角色权限关联 Mapper
- `PermissionService.java` + `PermissionServiceImpl.java` - 权限服务
- `RoleService.java` + `RoleServiceImpl.java` - 角色服务（支持权限保存）
- `PermissionController.java` - 权限接口
- `RoleController.java` - 角色 CRUD 接口

**修改文件：**
- `RoleMapper.java` + `RoleMapper.xml` - 新增 insert/update/delete 方法
- `UserController.java` - 删除重复的 `/api/roles` 接口
- `PermissionServiceImpl.java` - 超级管理员强制拥有所有权限

#### 2. 前端

**新增文件：**
- `src/api/permission.ts` - 权限 API
- `src/views/system/RoleList.vue` - 角色管理页面（含权限树配置）

**修改文件：**
- `src/router/index.ts` - 新增角色管理路由
- `src/utils/constants.ts` - 菜单项增加 permission 字段
- `src/stores/user.ts` - 新增 permissions 存储和 hasPermission 方法
- `src/layouts/DefaultLayout.vue` - 菜单根据权限动态过滤

#### 3. 权限数据

基于现有菜单结构，共 27 个权限编码：
```
dashboard, ai.assistant, ai.knowledge
warehouse.list, warehouse.shelf, warehouse.special
product.list, product.sku
stock.query, stock.log, stock.check
order.list, outbound.list, returns.list, exchange.list
express.query, express.company, express.template, express.report
system.users, system.roles, system.files, system.logs
system.stock-alert, system.stock-alert-template, system.platforms, system.backup
```

#### 4. 特殊逻辑

- 超级管理员（SUPER_ADMIN）强制拥有所有权限，不受角色配置限制
- 角色管理页面隐藏超级管理员角色
- 登录后自动获取权限列表，菜单动态过滤

### 使用方式

1. 执行 `wms-backend/sql/permission-seed.sql` 初始化权限数据
2. 以 SUPER_ADMIN 登录，进入"系统管理 → 角色管理"
3. 创建新角色，勾选可访问的权限模块
4. 创建用户分配该角色
5. 以该用户登录，只能看到被授权的菜单

## 三、自动备份与远程备份

### 背景

数据库备份需要手动操作，且只能保存在本地。需要支持定时自动备份和上传到远程服务器。

### 实现内容

#### 1. 自动备份

- 使用 Spring `@Scheduled` 定时任务
- 支持配置 cron 表达式（每天凌晨 2:00 / 3:00 / 12:00 等）
- 可选全量备份或增量备份
- 默认关闭，需在备份设置中开启

#### 2. 远程备份

- 使用 SCP 协议上传备份文件到远程服务器
- 支持配置远程主机、SSH 端口、用户名、密码、路径
- 提供测试连接功能
- 自动备份时如果启用了远程备份，会自动上传

#### 3. 新增文件

**后端：**
- `BackupConfig.java` - 备份配置实体
- `BackupConfigMapper.java` + `BackupConfigMapper.xml` - 配置 Mapper
- `BackupScheduler.java` - 定时任务调度器
- `RemoteBackupService.java` - 远程备份服务（SCP）
- `backup-config-table.sql` - 配置表 SQL

**前端：**
- `backup.ts` - 新增配置 API（getBackupConfig, saveBackupConfig, testRemoteConnection）
- `BackupManage.vue` - 新增"备份设置"按钮和配置弹窗

#### 4. 新增接口

| 接口 | 说明 |
|------|------|
| `GET /api/backup/config` | 获取备份配置 |
| `POST /api/backup/config` | 保存备份配置 |
| `POST /api/backup/config/test-remote` | 测试远程连接 |

### 使用方式

1. 执行 `wms-backend/sql/backup-config-table.sql` 创建配置表
2. 进入"系统管理 → 数据库备份"
3. 点击"备份设置"按钮
4. 开启自动备份，选择备份类型和时间
5. 如需远程备份，开启并配置远程服务器信息
6. 点击"测试连接"验证配置
7. 保存配置

### 注意事项

- 远程备份使用 sshj（纯 Java SSH 库），不依赖系统命令，跨平台可用
- 需要远程服务器开启 SSH 服务
- 远程目录需存在且有写入权限
- 备份时间改为 HH:mm 格式（如 02:00），不再使用 cron 表达式

## 四、问题修复记录

### 1. 仪表盘缓存不更新

**问题：** 完成订单后仪表盘数据不更新

**原因：** 仪表盘有 5 分钟缓存，但订单状态变更时没有清除缓存

**修复：** 在以下操作中添加 `cacheService.delete("cache:dashboard")`：
- `OrderServiceImpl.updateStatus()` - 订单状态变更
- `OrderServiceImpl.importOrder()` - 订单导入
- `OutboundServiceImpl.confirm()` - 出库确认
- `ReturnServiceImpl.confirm()` - 退货确认
- `ExchangeServiceImpl.ship()` - 换货发货

### 2. 库存预警权限错误

**问题：** 子账户访问仪表盘显示"无权限"

**原因：** `StockAlertConfigController` 和 `StockAlertTemplateController` 使用了错误的权限编码 `stock`

**修复：**
- `StockAlertConfigController` 权限改为 `system.stock-alert`
- `StockAlertTemplateController` 权限改为 `system.stock-alert-template`

### 3. 角色管理接口冲突

**问题：** 启动时报 `Ambiguous mapping` 错误

**原因：** `UserController.listRoles()` 和 `RoleController.list()` 都映射到 `GET /api/roles`

**修复：** 删除 `UserController` 中的 `listRoles()` 方法

### 4. 超级管理员权限限制

**问题：** 超级管理员被权限系统限制

**修复：**
- 后端：`PermissionServiceImpl.getPermissionCodesByUserId()` 检测到 SUPER_ADMIN 直接返回全部权限
- 前端：`hasPermission()` 已有判断 `if (roles.includes('SUPER_ADMIN')) return true`

### 5. 角色管理页面优化

- 隐藏超级管理员角色
- 移除表格 ID 列
