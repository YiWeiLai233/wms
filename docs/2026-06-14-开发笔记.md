## 一、退货管理增强

### 1.1 取消退货功能
- 新增 `POST /api/returns/{id}/cancel` 接口，按退货单ID取消
- 新增 `POST /api/returns/cancel-by-order/{orderId}` 接口，按订单ID取消
- 取消后：退货单状态→`CANCELLED`，订单状态→`SHIPPED`（可重新创建退货）
- 支持状态：待质检、可售待入库、次品待入库、报废待处理
- 使用 `@Transactional` 保证退货单和订单状态更新在同一事务内
- `ReturnOrderMapper.findLatestByOrderId` 查询订单最新未取消的退货单

### 1.2 客户退货快递单号
- `return_order` 表新增 `tracking_no` 字段
- 退货创建时支持传入客户快递单号
- 退货列表表格显示「客户快递单号」列
- 订单管理退货弹窗增加快递单号输入框（选填）

### 1.3 发货自动创建退货单
- 确认出库发货后，自动创建退货单（状态=待质检）
- 退货明细从出库明细自动复制
- 订单状态自动更新为「退货中」
- 用户无需手动创建退货，直接在退货管理页面操作质检和入库

## 四、库存扣减逻辑重构

### 4.1 扣减时机变更
| 操作 | 之前 | 现在 |
|---|---|---|
| 订单导入 | 不动库存 | **立即扣减库存** |
| 创建出库单 | 不动库存 | 不动库存 |
| 确认出库 | 扣减库存 | **不动库存** |
| 取消出库 | 不动库存 | **恢复库存** |
| 取消订单 | 不动库存 | **恢复库存** |

### 4.2 扣减算法优化
- `deductStock` 改为 while 循环 + 每次重新查询
- 避免同 SKU 多次扣减时数据过期问题
- 错误信息带 SKU ID 和剩余数量，方便排查

### 4.3 恢复库存流水修正
- `restoreStock` 方法在 `addQuantity` 之前保存 `beforeQty`
- 修正 `quantityAfter` 计算：`beforeQty + quantity`
- 之前错误：`addQuantity` 后 `stock.getQuantity()` 已更新，导致流水记录错误

ALTER TABLE outbound_order ADD COLUMN express_company_id BIGINT DEFAULT NULL COMMENT '快递公司ID' AFTER tracking_no;

## 技术要点

1. **事务管理**：取消退货使用 `@Transactional` 保证退货单和订单状态一致性
2. **库存扣减**：while 循环 + 每次重新查询，避免并发和数据过期问题
3. **自动创建**：发货后自动创建退货单，减少人工操作
4. **URL 参数跳转**：订单管理跳转到出库/退货管理时带 `orderNo` 参数自动筛选
5. **仓库类型路由**：退货入库按质检结果自动路由到对应类型仓库
